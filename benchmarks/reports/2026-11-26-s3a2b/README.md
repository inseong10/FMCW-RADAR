# S3a-2b — 분할 경로 결합 단계 감축 (결과 비트 동일)

- **날짜:** 2026-11-26
- **표기:** M(chirp)×N(샘플)
- **문제:** S3a-2 PL 256×128에서 FFT 단계 9.953ms 가운데 E14 두 번(약 2.8ms)을 뺀 약 7ms가 재배치와 결합 단(방법 A)이었다.
  - 결합 버터플라이는 셀마다 비인라인 `fft128_real/imag/pack` 6회와 int64 `/`·`%` 4회를 썼다.
  - ARM32에서 int64 `/`·`%`는 라이브러리 호출이다.
- **변경:** `src/PS/receiver/stream_pipeline.hpp` `b07a6883…` → `2ba1c7f5…`. 원본은 `build/s3a2b_pre_20261126/`에 있다. **분할 경로만** 바꿨고, 128×128 경로(`transform128`)는 그대로다.
  - 버터플라이를 int32만으로 계산한다.
    - 곱 각각 |br·wr| ≤ 2^30이다.
    - P = 2^15·h + l(0 ≤ l < 2^15)이면 floor((A·2^15+P)/2^16) = (A+h)>>1이고, floor((A·2^15−P)/2^16) = (A−h−(l≠0))>>1이다.
    - h와 l은 각 곱의 15비트 분할과 borrow/carry로 구한다. 디코드와 팩은 인라인이다.
  - PL: 블록을 E14 요청 입력에 직접 모으고 요청 출력에서 직접 배치한다(블록당 16,384워드 복사 2회 제거). model은 기존처럼 sub_in/sub_out을 쓴다.
  - 중간판 `new`(int64 시프트 floor)도 측정해 보존했다.
- **테스트 추가:**
  - `tests/bench_s3a2.cpp` `e5b9f508…`: 분할 경로 덤프와 시간
  - `tests/micro_s3a2.cpp` `63ee6656…`: 모으기·배치·결합만 측정
  - `tests/butterfly_s3a2_equiv.cpp` `a1be217b…`: 이전 int64 버터플라이와 등가성
  - micro와 equiv는 bench 사본에서만 `private:`→`public:`로 바꿔 빌드한다(`bench/src/`).

## 해석

- 결과는 그대로이고, 256×128 PL 처리 시간이 17.1→12.2ms(주기 대비 67→48%)로 줄었다.
- R축 S3a-3(N=256, 12.8ms)은 같은 셀 수다. 결합(2.25ms)과 strided 모으기(0.88ms)가 더 크므로 현재 처리 합계로는 경계이거나 초과로 예상한다(계산값, 미측정).
