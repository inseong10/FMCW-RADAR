# E09: 순차 20 MHz 경로의 시간 분해

[전체 실험 일지](../../../docs/experiment_log.md)의 E09에 해당한다.
입력과 펌웨어는 기존 순차 20 MHz 기준선을 사용한 흐름이다. 이 실행 시 보드 바이너리·펌웨어
해시는 다시 제공받지 않았으므로 새로 검증한 해시로 기록하지 않는다.

```sh
sudo sh /opt/fft128/benchmark/profile_board.sh 20000000
```

CPU0, 워밍업 2회, 계측 20회, `FRAME_PASS ... bit_exact_bins=16384`.
`console_excerpt.log`는 사용자가 붙여넣은 콘솔의 핵심 부분을 옮긴 것으로, 줄바꿈을 정리했고
전체 원시 terminal dump는 아니다. `summary.json`은 해당 콘솔 수치와 명시된 역산값이다.

| 값 | 시간 |
|---|---:|
| 입력 쓰기 평균 | 23.429884 ms |
| 시작·대기 평균 | 39.927098 ms |
| 출력 읽기 평균 | 18.370430 ms |
| gather/scatter 평균 | 0.947203 ms |
| 전체 평균 / 중앙값 | 83.694257 / 83.623717 ms |
| 전체 최소 / 최대 | 83.532463 / 83.902585 ms |
| 하드웨어 counter / FFT | min=max=3,073 |
| PL 내부 구간 | 39.334400 ms = 3,073×256/20 MHz |

PL 내부 구간은 시작·대기와 겹친다. 입력+출력 MMIO는 41.800314 ms이며,
카운터 읽기와 기타 잔여의 합 1.019642 ms는 전체에서 콘솔에 표시된 호스트 단계를 뺀 값이다.
이 잔여 안의 세부 비중은 콘솔만으로 분리할 수 없다.

**원본 수집·검증 완료:** 프레임별 `.profile.csv`, 수신기 JSON·시간 CSV,
`analyze_profile.py`의 `.profile.summary.json`과 `collected_validation.json`을 추가했다.
기존 콘솔 요약은 그대로 보존한다. 입력 해시와 16,384개 출력이 기준선 및 새 pipeline 결과와 같다.
파일명 `profile_20180309_150010`의 날짜는 보드 시계이며 실제 기록일은 2026-11-15다.
계측 없는 E08과 같은 표본으로 합치지 않는다.
