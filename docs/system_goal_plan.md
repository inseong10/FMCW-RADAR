# 시스템 목표와 단계 계획 (S1~S3)

작성 2026-11-25. FFT 가속(E01~E14)은 [단계별 가속 계획](fft128_dma_plan.md)과
[실험 일지](experiment_log.md)에 있다. 이 문서는 그 위의 **시스템 목표**와 다음 단계를 정한다.
각 단계의 실행 과정·실패·해결은 실험 일지에 S ID로 기록한다.

## 1. 왜 목표를 다시 정하는가

- [프로젝트 계획서](FMCW%20레이더%20신호처리%20시스템%20프로젝트%20계획서.pdf)(10-27)의 목표는
  연속 프레임 처리, 검출 정확성, 크기별 PS/PL 파티셔닝, 상시 계측 네 가지다.
- E01~E14는 그중 **같은 프레임 반복의 단일 FFT 지연**만 줄였다. E14 PL 1.657914 ms,
  같은 회차 NEON 3.489441 ms 모두 현재 프레임 간격 12.8 ms(128 chirps × PRP 100 µs) 안이다.
  따라서 128×128에서 FFT 지연을 더 줄여도 계획서 목표 1의 합격 여부는 바뀌지 않는다.
- 아직 없는 것: CFAR·ground truth 비교, 연속 UDP 처리, 드랍·P99·CPU 계측, 크기 스윕.

## 2. 목표 정의

- **주 목표:** UDP 수신 → FFT → CFAR → 출력의 end-to-end 경로에서, 입력 크기별로
  **드랍 0과 P99 처리 시간 < 프레임 주기를 유지하는 최대 프레임률**을 PS-only와 PS+PL에서 측정하고 교차점을 제시한다.
- **정확성:** 검출한 타겟의 거리·속도 bin이 ground truth의 기대 bin과 ±1 bin 안에서 일치하고,
  오검출 수를 함께 기록한다. FFT bin 수치 일치(기존 검증)는 하위 검사로 유지한다.
- **제약:** Zybo Z7-10(XC7Z010) 자원, PetaLinux soft real-time, 시뮬레이터 입력.
- **보조 지표:** CPU 사용률, 메모리, PL 자원·타이밍, 단일 프레임 지연.

## 3. 현재 입력의 기대 검출 위치 (계산값, 미검증)

입력: [고정 기록](../benchmarks/fixtures/README.md) 128×128, fs 1.6 MHz, chirp 80 µs, PRP 100 µs,
24.0~24.1 GHz, 표적 30 m / -10 m/s.

| 항목 | 계산 | 값 |
|---|---|---|
| chirp 기울기 | 100 MHz / 80 µs | 1.25e12 Hz/s |
| 거리 분해능 (bin 간격) | c / (2B) | 1.5 m |
| 30 m의 beat 주파수 | 2R·slope / c | 250 kHz |
| Range bin | 250 kHz / (1.6 MHz / 128) | **20** |
| 파장 (24.05 GHz) | c / fc | 12.474 mm |
| Doppler 주파수 | 2v / λ | -1603.4 Hz |
| 속도 분해능 | λ / (2 · 128 · 100 µs) | 0.487 m/s |
| Doppler bin | -1603.4 / 78.125 = -20.52 → 128 - 20.52 | **약 107.5 (107 또는 108)** |

- E11b 기록의 NumPy 피크 (107, 20)와 일치한다. Doppler는 bin 사이(-20.52)에 걸려 있어
  ±1 bin 허용이 필요하다. 부호 규약(-10 m/s ↔ bin 107)은 S1a에서 ground truth로 확정한다.
- S1a에서 고정 기록이 무잡음임을 확인했다. 단일 표적·무잡음 조건이므로 CFAR 오검출 평가에는 다중 표적·잡음 시나리오가 추가로 필요하다.

## 4. 단계와 합격 조건

| ID | 질문 | 변경 | 합격 조건 | 상태 |
|---|---|---|---|---|
| S1a | CFAR 기준 모델이 ground truth를 찾는가 | PC NumPy 2D CA-CFAR 기준 모델, 다중 표적 입력 추가 | 모든 표적 ±1 bin 검출, 오검출 수 기록, 파라미터 고정 | PC 완료(잠정 hann+CA). 고정 기록 무잡음 확인 |
| S1b | 보드 PS에서 같은 검출이 나오는가 | 수신기에 CFAR 추가(PS FFT 경로) | S1a와 검출 목록 일치, CFAR 시간 측정 | 계획 |
| S1c | PL FFT(Q15) 결과로도 같은 검출이 나오는가 | E14 경로 뒤에 같은 CFAR | S1a와 일치 여부, Q15 영향 기록 | 계획 |
| S2a | 연속 처리를 관측할 수 있는가 | FrameMonitor·ResourceSampler, 타임스탬프 CSV | 프레임별 수신·처리·출력 시각, 드랍, CPU·메모리 기록 | 계획 |
| S2b | 12.8 ms 주기 연속 입력을 처리하는가 | 연속 UDP 송신, 수신 큐 | 장시간(예: 10,000 프레임) 드랍 0, P99 < 12.8 ms | 계획 |
| S2c | 최대 지속 프레임률은 | 송신 주기 스윕 | PS-only / PS+PL 각각 한계 주기와 병목 | 계획 |
| S3a | PS는 크기에 따라 어떻게 변하는가 | 64~512 크기 입력·ground truth | 크기별 최대 프레임률·CPU | 계획 |
| S3b | PL 구조는 크기에 따라 어떻게 바뀌어야 하는가 | RTL 크기 파라미터화, E14 방식이 안 들어가는 크기의 구조(E15-memory) | 크기별 자원·타이밍·최대 프레임률, PS와의 교차점 | 계획 |

순서는 S1 → S2 → S3이다. PS02·E11c·E11d는 S2c에서 병목으로 확인될 때만 실행한다.

## 5. 기록 규칙

- 각 S 단계는 실험 일지에 **질문 → 변경 → 검증 경과 → 결과 → 해석 → 다음** 순서로 적고,
  막힌 지점과 해결 과정도 "검증 경과"에 남긴다. 실패한 시도는 지우지 않는다.
- 근거는 `benchmarks/reports/<날짜>-<S ID>/`에 둔다. 증거 종류(PC 시뮬레이션·보드 실측·콘솔·계산값)를 구분한다.
- 위 3절의 기대 bin은 계산값이며 측정이 아니다.
